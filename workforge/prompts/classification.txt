Мы фильтруем объявления о проектах (например, с FL.ru), чтобы находить задачи для software engineering outsourcing компании и отсеивать нерелевантные заказы.

Используется система маркеров:

Позитивные маркеры — признаки задач разработки
Негативные маркеры — признаки нерелевантных задач
Стоп-маркеры — если найден хотя бы один, объявление считается мгновенно забаненным.

В следующих сообщениях я пришлю списки маркеров и затем объявления.

Твоя задача — анализировать объявления.

ПРАВИЛА ПОИСКА МАРКЕРОВ

Поиск выполняется только по точному вхождению подстроки.

Правило: marker находится в тексте

Запрещено:
- стемминг
- лемматизация
- семантические догадки
- транслитерация
- поиск похожих слов

Примеры:
чатбот ≠ чат-бот
съемк ≠ съёмк
стр. ≠ строчек

Если точной подстроки нет — совпадения нет.

ЛЕВАЯ ГРАНИЦА МАРКЕРА

Маркер учитывается только если слева от него нет буквы.

Формально:
marker найден в тексте
и
либо это начало строки
либо символ слева не является буквой

Пример:
маркер: аут

аутрич → совпадение
B2B-аутрич → совпадение
воркаут → НЕ совпадение

ПОДСЧЕТ СОВПАДЕНИЙ

Если один и тот же маркер встречается несколько раз — он считается только один раз.

Пример:
маркер: логотип
текст содержит слово "логотип" 5 раз

результат: считается 1 совпадение.

ЕСЛИ УКАЗАНО КОЛИЧЕСТВО МАРКЕРОВ

Если в объявлении есть строка:
Позитивные/Негативные/Стоп: X/Y/Z

то:
- нельзя пересчитывать количество
- нельзя пытаться определить какие именно маркеры дали эти значения

ВАЖНО
Анализируется только тот текст объявления, который реально присутствует в сообщении.

Нельзя:
- использовать обрезанные части текста
- предполагать продолжение после "..."
- учитывать текст со страницы по ссылке

Если маркер не найден в видимом тексте — его нет.


ПРЕДЛОЖЕНИЕ НОВЫХ МАРКЕРОВ

Когда я прошу предложить новые маркеры:
нужно предлагать короткие устойчивые подстроки, которые помогут фильтровать будущие похожие объявления, а не только текущее.

Правила:
- маркер должен встречаться в разных объявлениях
- нельзя предлагать уникальные фразы из одного текста
- нельзя предлагать доменные термины
- нельзя предлагать универсальные слова
- очень короткие маркеры (2–3 буквы) предлагать с осторожностью

Нельзя:
- предлагать маркеры, которые уже есть в списках.
- предлагать вариации уже существующего маркера.

ВАЖНО
Не предлагать маркеры, которые могут встречаться в IT-заказах.

Примеры плохих негативных маркеров:
персонаж
игра
локация
стоматолог
квартир
карт
3d модел
vpn
маркетплейс
разработк
настройк


ОГРАНИЧЕНИЯ

Нельзя:
- придумывать маркеры которых нет в списке
- писать, что сработал маркер если его нет в списке
- считать совпадением разные слова

Примеры

стр. ≠ страниц
доставк ≠ доставлен
конверси ≠ конвертация
издели ≠ отверстие

ФОРМАТ СОВПАДЕНИЯ
маркер → совпавшая подстрока

Пример
дизайнер → дизайнера
статус → статусов

ЗАДАЧА ПРИ РАЗБОРЕ ОБЪЯВЛЕНИЯ

Нужно:
1. Предложить все новые маркеров, которые помогут фильтровать это конкретное объявление
2. Предложить 10-15 новых маркеров, которые помогут фильтровать этот класс объявлений.

Ответ просто "Ок", если всё понятно.
